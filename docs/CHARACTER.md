# ポップン

GitHubにユーザーが追加した4枚の透過PNGを、そのまま使用します。画像の加工・背景の追加・縦横比の変更は行いません。

| ファイル（assets/characters/） | 表示 |
| --- | --- |
| pop_idle.png | 通常・待機 |
| pop_correct.png | 手動で1語正解 |
| pop_chain2.png | 2連鎖 |
| pop_chain3.png | 3連鎖以上 |

## 表示と動き

画像は既存のキャラクター枠に `object-fit: contain` で収め、盤面上端から顔を出す配置です。デスクトップは238px四方、モバイル幅は180px四方の表示領域。PNG本来の透過を使い、正方形の背景は付きません。装飾は `pointer-events: none` とし、なぞりを妨げません。

待機中は4秒周期で4pxほどゆっくり上下します。正解・連鎖で0.5秒の軽いジャンプを付けます。表情は連鎖中そのまま維持し、すべての消去・落下が終わってから650ms後に通常へ戻します。次の正解やリトライが先に来たら、以前の復帰タイマーを取り消します。`prefers-reduced-motion: reduce` では動かず、画像の切り替えだけ行います。

## 読み込み失敗

4枚は起動時に非同期で先読みします。読み込み待ちや失敗でゲーム進行を止めません。ある表情が未配置なら通常画像、それも使えなければ従来のCSS仮キャラクターを表示します。読み込みが遅れて完了した場合も、現在の表情へ反映します。後から画像を追加・差し替えた場合は画面を再読み込みしてください。

## 変更範囲

`character.js` が画像キャッシュ・表情・復帰タイマーを管理。`index.html` に表示領域とスクリプト、`style.css` に画像の表示と動きを追加しました。`game.js` の変更は `react(chain)`、`finish()`、`reset()` の通知3行です。盤面・得点・判定・補充・連鎖のルールは変更していません。

## 検証

HTTPサーバーとPlaywright/Chromiumを用意して `node tests/character-browser.cjs` を実行します。4枚の読み込み、正解・2連鎖・3連鎖以上、連鎖中の維持、復帰タイミング、古いタイマーの取り消し、PC/390px/320px、動きを減らす設定、画像404でも遊べることを確認します。

連鎖イベントの表示順テストには、UI表示を再現するため固定の連鎖候補を返すテスト用盤面を使っています。通常の盤面でのゲームルールは既存の `tests/*.test.cjs` と `tests/browser.cjs` で検証します。スマートフォン実機・Safariでの確認は未実施です。

UI整理で表示サイズを約1.4倍へ変更しています。全身ポーズはCSSで顔の位置と見かけの大きさを補正し、下半身を表示領域で切り取ってフレームの裏に隠します。元のPNGを加工・変形せず、表情の切り替えとアニメーションのタイミングは維持しています。

## 画像を読み込めない場合の復帰

iPhone/Safariの公開URLで仮キャラになるという報告を受け、読み込みを補強しました。

- 画像はHTMLページのURLではなく、`character.js` の配置URLから相対解決。
- HTMLのCSS/JavaScript参照とPNGに更新識別子を付け、旧版や古い画像エラーのキャッシュと区別。
- 通常画像の取得優先度を高くし、読み込み済みの同じ画像を不要にDOMへ挿し直さない。
- 画像エラーまたは12秒のタイムアウトでは、1.2秒後・2.4秒後の最大2回だけ再試行。再試行時は時刻付きURLにして、以前の404キャッシュを再利用しない。
- 復帰したら現在の表情へ反映。すべて失敗しても仮キャラを維持し、ゲームは進める。

`node tests/character-recovery-browser.cjs` では、iPhone/Android相当のChromiumで初回404を再現し、4枚の復帰・回数上限・別ディレクトリのページからの解決を確認します。Safari実機の再現テストではありません。

この作業環境ではGitHub Pagesの公開ドメインとWebKitの取得先がネットワークポリシーで拒否されたため、公開サイト上の応答とSafariエンジンでの検証は実施できていません。原因をSafari固有不具合や公開先404と断定したものではなく、実装上確認できた「失敗すると再試行しない」問題への対策です。GitHub Pagesの反映後に更新確認用URLで実端末確認します。
