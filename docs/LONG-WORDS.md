# 5〜6文字を見つけやすくする調整

短い単語しか見つからないというプレイ感想を受け、配置とヒントを長い単語中心へ変更しました。画面・操作・得点計算・最大連鎖数は維持しています。

## 語彙の使い分け

正解として認める3,000語はそのままです。語彙を消して短い単語を不正解にするのではなく、**盤面に置く候補を、日本語訳のある5〜6文字157語に絞って**います。APPLE、ORANGE、BANANA、FLOWER、SCHOOL、RABBITなどが候補です。日本語訳は既存のものを表示します。複数形・過去形を追加するものではありません。

## 初期盤面

5文字3語、6文字3語の、少なくとも6種類を横一直線に配置します。毎回候補を抽選し、同じ語を重ねて配置しません。チュートリアルのCAT経路、縦のBOOK、DOG、SUNも維持しています。最初の1語だけは従来どおりCATの案内です。

## 補充

以前の「通常補充は常にランダム」という方針から、今回の長い単語の発見を優先する方針へ変更しました。

まず通常の重み付き文字抽選と落下を行います。その後、5〜6文字が合計3種類未満、または5文字・6文字のどちらかがない場合に、長い単語ができる補充を検討します。

- 新しく入るマスだけを調整します。既存の落下文字は書き換えません。
- 今の盤面にない語を優先し、不足している文字数の候補があればそれを優先します。
- 長い語が複数残っていて5文字・6文字の両方があるときは、ランダム補充のままにします。
- 一度に作るのは最大1語。可能な配置がなければそのまま終了し、再抽選を無限に繰り返しません。

3文字を消しただけでは、既存文字と合う5〜6文字の候補が見つからないこともあります。毎手3種類以上の長語を保証するものではありません。5〜6文字を消した場合は新しいマスも多くなり、次の長い単語を補充しやすくなります。

## 連鎖との関係

5〜6文字は手動で見つける対象です。自動連鎖の対象は従来どおり身近な3〜4文字のみ。補充で意図的に配置した長い単語は、その補充直後の連鎖判定では保護し、中のEARやARTなどだけで即消去しません。その他の偶然の連鎖は維持します。

## ヒントと残り語数

初回のCAT以外は、15秒ヒントで5〜6文字を優先します。両方ある場合は、ヒントを出すたび5文字・6文字を交互に選びます。長い語がなければ短い語へ戻します。

盤面下の表示は「5〜6文字の単語 ○ 個」に変更しました。これは訳付き157語のうち、今の盤面で作れる種類数です。同じ語の複数経路は1個と数えます。

## 検証

```sh
node --test tests/*.test.cjs
node tests/long-words-browser.cjs
```

初期の5文字3語・6文字3語、訳と登録語の整合、補充時の既存文字の保持、長語の保護、連続30手の6文字消去を検証します。実ブラウザでも5文字・6文字のヒント、6回の長語消去、得点、日本語訳、継続補充、スマートフォン幅を確認します。従来のブラウザ操作・ヒント・演出テストも実行します。
